# Wildscape

- Solo-developed 3D sandbox survival RPG using Godot 4 and GDScript.
- Exploration, gathering, crafting, building, inventory, equipment, loot and RPG progression are directions, not finalized requirements. Singleplayer first; co-op may follow later. Art style is undecided.
- Keep the foundation small, stable and expandable. Implement only the requested scope; avoid speculative systems, frameworks, managers and autoloads.
- Current baseline: Godot 4.7.2 stable, Compatibility renderer. Coordinate engine or renderer changes explicitly.
- Use snake_case for files, folders, functions and variables; PascalCase for node and class names. Prefer typed GDScript where practical.
- Use tabs for GDScript indentation and LF line endings (see .gitattributes). One Godot unit is one meter; player scene origin is at the feet. Physics layer 1 is World, layer 2 is Player.
- Keep scenes and their related scripts together under scenes/. Add feature folders and shared resources only when used. Preserve Godot-generated .uid sidecars and resource .import metadata; never version .godot/.
- Main composes the reusable player and development playground. Keep movement/collision in the player script and replaceable geometry under Visuals. Gameplay beyond the controller/playground still requires a specific request.
- F5 starts scenes/menus/main_menu.tscn. scenes/main.tscn remains the independently runnable gameplay scene (F6). The scene-local MenuController alone owns pause, scene transitions, focus handling and OS mouse capture; the player's set_mouse_captured method only gates gameplay input.
- Gameplay root uses Pausable process mode; only the menu CanvasLayer uses Always. Keep gameplay outside that Always subtree. Focus loss pauses; focus return never resumes automatically. Returning to main menu must clear SceneTree.paused.
- After project/resource changes, run headless import and a bounded startup as documented in README.md. Check output and exit codes; headless success does not validate graphics. Test graphical startup when available and report any untested behavior.
- Run tests/player_smoke_test.gd after controller, camera, input or collision changes. It uses native Godot physics and simulated input; no external test framework is required. Interactive camera feel and visual quality still need manual testing.
- Also run tests/interaction_smoke_test.gd after movement/interaction changes. WorldInteractable is the local interaction contract; keep interactables and blockers on the World layer. Camera aim, player-eye range and player-eye line of sight must all pass before activation. Do not add global interaction managers.
- Run tests/run_tests.ps1 (supply -GodotPath; add -Graphical when available) for the import, all seven suites and startup checks. It detects logged errors even with exit code 0. The existing physics/3d/physics_engine setting is DEFAULT (GodotPhysics3D); do not silently switch it to Jolt.
- Static ItemDefinition resources live in data/items/. IDs are hand-authored stable lowercase identifiers; do not derive them from display names or change them casually. ItemCatalog validates and snapshots definitions; inventory reads return detached stack/definition copies.
- Player owns an initially empty 6x6 SlotInventory and six-slot EquipmentInventory sharing one catalog. Quantities, position and rotation belong only to runtime state; modify them through validated operations, never through item resources or UI copies. Transfers require a shared catalog (get_catalog()). Populated inventory fixtures belong exclusively in tests/fixtures/; world supplies in the playground must require interaction and never seed player inventory automatically.
- Grid indices are row-major top-left anchors. get_stack() returns anchor snapshots only; a covered cell is occupied even when its get_stack() is null. Resolve cells with get_anchor_at(). Use can_place/get_addable_at/get_transfer_amount for UI previews and validated operations for commits. Full moves may overlap their own old footprint; partial moves/splits may not.
- Equipment compatibility uses ItemDefinition.EquipmentSlot flags for Head, Chest, Legs, Feet, Primary and Secondary. Each slot holds exactly one unit. Equip/unequip must preserve quantities and both models' notifications. No effects, implicit swaps or backpack behavior. Run grid_inventory_test.gd after placement/equipment changes.
- InventoryView observes injected inventory/equipment and owns only transient drag snapshots. MenuController alone owns Tab/C/Escape transitions, pause and mouse state. Either window pauses the world; closing one must preserve the other's pause. Escape closes both; focus loss cancels drags and closes both into the pause menu without resetting data. Shift-drag splits half; R rotates the preview. Validate through model APIs, recheck source snapshots and commit only on a valid release. Run inventory_model_test.gd and inventory_ui_test.gd after inventory changes.
- Do not install tools/plugins or create commits, pushes or merges without user authorization.
- WorldItemSource is the shared WorldInteractable implementation for world_pickup.tscn and gathering_source.tscn. Actors expose get_inventory(); item IDs resolve through that inventory's catalog. Subtract only SlotInventory.add()'s actual return value. Keep the source locked through inventory and interaction signals, reject invalid configuration, respect pause, and retain partial quantities. Run world_collection_test.gd after collection changes; there are no tools, respawns, loot tables or saved resource states.
